# Dearly 1.0.1 RC1 — sign-in timeout fix

The first hosted APK canceled all API requests after ten seconds. A real phone
attempt timed out, and its server-side WhatsApp submission remained UNKNOWN.
The app could therefore leave sign-in before an operation had finished.

HTTPS API requests now have a bounded three-minute deadline, allowing time for
free-host cold starts. Explicit caller deadlines and cancellation remain supported;
local HTTP development keeps its ten-second default. Hosted WAHA readiness has a
60-second deadline and a submission has 30 seconds. No POST or OTP is automatically
retried; an uncertain submission remains uncertain and still consumes its budget.
No code, recipient, private link or gateway response is added to logs.

Regression checks cover a hosted request completing after the old ten-second
limit, bounded timeout without a duplicate OTP, and abort-aware simulated gateway
readiness plus submission that each exceed ten seconds. Frontend checks passed
83 tests; backend checks passed 103 tests, types, lint and compilation. No live OTP
was sent for automated validation. Real sign-in on the recipient phone remains a
user check after installing the update.

Version is 1.0.1; Android build number 3 and iOS build number 3. The signed ARM64
APK updates the earlier build using the same package/signing identity. Earlier
release assets and tags are preserved. Physical push testing remains deferred.
