# Dearly — Mobile Application Project Plan

Major Project · React Native · Full Stack · Medium Difficulty

**Tagline\:** *Some messages are worth waiting for.*

## 1\. Project Overview

**Dearly** is a future-message delivery application where users can create and schedule personalized messages for themselves, friends, family, or anyone using their phone number or email address.

Messages can contain text, photos, videos, voice recordings, and other attachments. They are automatically delivered on a selected date and time, making Dearly suitable for birthdays, anniversaries, graduations, surprises, and future memories.

## 2\. Core Features

| Feature | Description |
|--------|--------|
| Phone Authentication | Login/signup using phone number and OTP |
| Create Message | Write text and attach photos, videos, audio, or files |
| Recipients | Send to yourself, another app user, a phone number, or an email |
| Scheduling | Select exact delivery date, time, and timezone |
| Occasions | Birthday, anniversary, graduation, New Year, custom events |
| WhatsApp Delivery | Send messages or secure message links through WhatsApp |
| SMS Delivery | Send text messages or links to phone numbers |
| Email Delivery | Deliver messages through an email service |
| In-App Delivery | Messages appear in the recipient's Dearly inbox |
| Notifications | Alerts when messages are received or opened |
| Message Management | Edit, reschedule, or cancel messages before delivery |
| Delivery Tracking | Pending, scheduled, sent, delivered, failed, and opened statuses |

## 6\. Important Delivery Considerations

- **WhatsApp\:** An open-source model cannot independently deliver WhatsApp messages. Automated delivery generally requires the official WhatsApp Business Platform, approved templates where applicable, and may incur charges. Avoid unofficial WhatsApp automation for reliable production delivery.
- **SMS\:** Sending SMS to arbitrary phone numbers requires a gateway or carrier service. Open-source software does not eliminate SMS delivery costs.
- **Email\:** Start with a free-tier transactional email service. Send media through secure links rather than large email attachments.
- **Phone OTP\:** Use a real OTP provider for production. A mock OTP flow is sufficient during early development.
- **Privacy\:** Keep scheduled messages private until their release date. Use expiring links and recipient verification for sensitive content.

## 7\. Development Phases

1. **Phase 1 — Authentication &amp; UI**

   Phone login, OTP verification, dashboard, profile, navigation.
2. **Phase 2 — Message Creation**

   Text editor, attachments, recipient selection, occasion selection, scheduling, drafts.
3. **Phase 3 — Message Management**

   Created, scheduled, sent, and received inboxes; message details; edit, cancel, and reschedule.
4. **Phase 4 — Automatic Delivery**

   Background worker, email delivery, in-app messages, push notifications, retries, and delivery logs.
5. **Phase 5 — Additional Channels &amp; Testing**

   Integrate WhatsApp and SMS where provider access is available, then test scheduled delivery, security, and edge cases.

**Recommended MVP\:** Complete phone authentication, multimedia messages, scheduling, email delivery, and in-app inboxes first. Add WhatsApp and SMS through supported providers afterward.

**Estimated development time\:** 4–6 weeks for a focused MVP, excluding delays for external messaging-provider approval.

This keeps Dearly achievable as a college major project while leaving room to expand into a real consumer application.
